## Reportar una Vulnerabilidad

Aunque este repositorio contiene principalmente contenido educativo (documentación, ejercicios, ejemplos), tomamos la seguridad en serio.

### ¿Qué reportar?

- 🔗 Enlaces maliciosos en la documentación
- 📝 Código de ejemplo con vulnerabilidades conocidas
- 🔑 Credenciales o secrets expuestos accidentalmente
- ⚠️ Configuraciones inseguras en ejemplos de GitHub Actions

### Cómo reportar

1. **NO** crees un issue público para vulnerabilidades de seguridad
2. Envía un correo a los mantenedores del proyecto
3. Incluye:
   - Descripción de la vulnerabilidad
   - Ubicación del archivo afectado
   - Pasos para reproducir (si aplica)
   - Impacto potencial

### Tiempo de respuesta

- **Acuse de recibo**: 48 horas
- **Evaluación inicial**: 7 días
- **Resolución**: Dependiendo de la severidad

## Buenas Prácticas de Seguridad

Este bootcamp enseña prácticas de seguridad en Git/GitHub. Como estudiante o contribuidor:

### ✅ Hacer

- Usar SSH keys en lugar de HTTPS con contraseñas
- Habilitar 2FA en tu cuenta de GitHub
- Revisar código antes de ejecutarlo
- Usar `.gitignore` para archivos sensibles
- Rotar secrets regularmente

### ❌ No hacer

- Commitear credenciales o API keys
- Compartir tokens de acceso
- Ejecutar código no verificado
- Ignorar alertas de Dependabot
- Deshabilitar protecciones de branch
